# Суточная память — v1

Реализация подготовлена; наличие исходников в Git не подтверждает включение работающей службы. Runtime остаётся в CinemaStudio/web/editorial-live/director и CinemaStudio/ai-character-pilot/browser/server.py. Новая операция требует обновления обоих процессов. Исходники сервиса в ai-character-pilot/ не содержат credentials, сеансов или памяти сцены. Предыдущий director/provider/openrouter_client.py остаётся историческим снимком адаптера; актуальный полный набор находится в ai-character-pilot/.

## Контракт

Для каждого персонажа смысловые события записываются в отдельный неизменяемый архив `STATE_FILE.memory-archive/<actor>/`. Записи выбора действия с action/at/fatigue_before/source не считаются воспоминаниями. Все действующие производители памяти используют addMemory: финансы, отношения/reflection, общение, сон, приглашения, работа, телефон, совместные напитки и телевизор. Это покрытие существующих источников событий, не утверждение полноты всех занятий.

В состоянии персонажа хранятся одна выбранная память и ограниченное окно свежих событий. Суточная память ЗАМЕНЯЕТ предыдущую, не добавляет новую ежедневную сводку. В обычный запрос попадает объединение по source ID без дублей, в порядке сохранения событий; сравнимые реальные даты дополнительно упорядочивает compactSnapshot. Старые факты и полные закреплённые правила идут раньше текущего состояния и доступных вариантов.

Точные пределы JSON UTF-8:

- выбранная память: до 12 исходных событий и 4000 байт;
- свежие события: до 12 и 4000 байт;
- объединение для обычного запроса: не более 8000 байт;
- кандидаты для суточного обновления: до 64 и 16000 байт;
- старый выбор + кандидаты: не более 20000 байт источников;
- ответ модели: только selected_ids, до 12 ID; генерация ограничена 600 токенами.

Модель выбирает source IDs; тексты фактов остаются исходными. Неизвестные/повторные ID, дополнительные поля, незаконченный ответ и превышение бюджета отклоняются. Свободная выдуманная сводка не принимается. Прежняя память и поступившие во время запроса события сохраняются при ошибке. Выбранные события из промежутков свежего окна не теряются.

Кандидаты — ограниченная выборка: последний пример каждого семейства событий/ответа, затем свежие события до лимита. Все исходные смысловые события остаются в архиве; модель не читает всю историю за сутки. Событие, которое само не помещается в бюджет, остаётся в архиве и не передаётся обрезанным. Полный архив, технические журналы и очередь недописанных событий никогда не добавляются к запросу.

Отбор полезности не имеет гарантии сохранения каждого важного воспоминания. Структурные лимиты гарантируются кодом. Действующие деньги, долги, договорённости, поручения, отношения и границы сохраняются в своих текущих источниках отдельно от исторического отбора. Их полнота проверяется существующим серверным сборщиком: если обязательное ядро не помещается, запрос блокируется. Это не обещание вместить произвольное число текущих обязательств.

## Расписание и запрос

Первое окно открывается через 24 часа после миграции. Затем — не чаще одной попытки за 24 часа на персонажа, только если появились кандидаты и есть видимый зритель. При отсутствии зрителей обслуживание откладывается; проверка выполняется перед подготовкой, после формирования и непосредственно перед отправкой. Если зритель исчез до POST, маркер попытки отменяется. Никакая автоматизация Codex для этого не создаётся.

POST /api/memory-consolidate использует ту же модель и закреплённые правила, общий session ownership, CALL_LOCK, предел 600 активных секунд/1000 вызовов и счётчик director. Сейчас выбран qwen/qwen3.7-flash, Alibaba, allow_fallbacks=false. Отбор не создаёт физической команды и не подменяет поведение. Транспорт вариантов применяет ту же alias/full-description обработку, что физические запросы.

Компилятор сохраняет полные источники суточного отбора и измеряет конечную обёртку. Действует прежний local_lexical_estimate_v1: strict=false, mode=estimated, допуск 25600 оценочных единиц контекста и 51200 всего запроса с резервом 20%. Это оценка, не точный токенизатор. Отсутствие счётчика или обязательное переполнение блокируют отправку провайдеру.

Маркер попытки сохраняется с fsync до POST. Перезапуск не создаёт повторный оплачиваемый запрос в том же суточном окне. Ошибки памяти имеют собственное следующее суточное окно; и current, и history показывают одинаковую политику. Ошибки physical/reflection по-прежнему сохраняют собственные блокировки. Память чередуется с физическими решениями, с приоритетом ответа владельцу и исполнения уже принятых команд.

## Сохранность

Ошибка архива не прерывает уже начатую денежную операцию. Факт остаётся в сохраняемой outbox и ограниченной памяти; модельные вызовы этого персонажа ждут успешной записи архива. Повторная запись того же ID идемпотентна. При перезапуске pending становится interrupted; дата предыдущей попытки и источники сохраняются. Архив после старого checkpoint читается потоково; восстанавливаются только факты памяти, без повторного начисления денег или исполнения действий.

## Проверка и включение

Новые тесты: `node --test test/daily-memory.test.mjs`; API/провайдер: `python3 -m unittest discover -s ai-character-pilot/browser/tests -p '*test.py'`. Транспорт провайдера фиктивный, ключи тестовые, реальные платные запросы не делались. Тесты охватывают 100000 шумовых записей, 3000 смысловых событий, 30 ежедневных замен, входящие события, отказ/сбой архива и повтор премии, gap в свежем окне, checkpoint recovery, исчезновение зрителя у каждого gate, replay/session ownership и final payload admission. Они не доказывают качество будущего модельного отбора.

Перед включением: сверить актуальные runtime файлы, применить только эту правку поверх новых параллельных изменений, дождаться границы без model pending/неподтверждённых команд. Обновить pilot service отдельным разрешённым действием; ключ загрузится штатно из Keychain, извлекать его не требуется. Перезапустить director с его новейшим состоянием. Для UI применить только обновлённый renderer model-status в текущем browser snapshot; не пересобирать несвязанные изменения рабочего дерева и не перезагружать вкладки владельца.

После включения: проверить source hashes, новый endpoint без платного вызова, сохранение денег/памяти/команд, продолжение сцены, ограниченные размеры и due markers. Реальный суточный отбор проверяется при естественном наступлении окна с видимым зрителем, без изменения нужд или таймера ради теста. Подробная панель памяти с независимым серверным подтверждением этой правкой не реализована.

Откат — вернуть только код этой функции, сохранив новейшее состояние и архив. Старый код игнорирует dailyMemory, продолжает использовать ограниченную p.memory; дополнительные отобранные источники остаются в dailyMemory/архиве для повторного включения. Не восстанавливать старый director-state.json и не удалять архив/outbox. После rollback временно прекращается дальнейшее архивирование новым helper; это требуется учитывать.
